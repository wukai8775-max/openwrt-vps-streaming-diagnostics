# 验收与恢复

## 先区分三种结果

1. **连得上**：SSID、接口、DHCP、DNS、握手和出口正确。
2. **合成任务能完成**：同一对象的完整下载、限速持续上传、小请求在规定预算内完成，失败分母完整。
3. **直播业务通过**：实际手机、实际平台、实际画质与并发数持续工作，在目标时段没有不可接受的卡顿、重连或互动延迟。

服务进程运行、出口国家正确、空载 CPU 低、一次测速快，只能覆盖其中一部分。没有手机时可完成前两层，第三层继续待验收。

## 合成验证记录

下载只有 curl 正常退出、HTTP 200、字节数与目标精确相等才算完成。超时的部分对象保留失败记录，不能用部分下载速度计算完整任务的完成时间提升。

上传记录每一条流是否完整、总字节数、HTTP 响应、持续时间及源地址。`--mbps` 是工具的每条流目标上限；三条 5 Mbps 流约 15 Mbps，不能推导生产线路只有 15 或 20 Mbps。

小请求记录全事务超时、所有尝试、成功响应延迟、首次连接与重连。STUN 探针超时率不是视频包丢失率，成功样本的 p95 也不能隐藏失败分母。固定对象、大小、地址、协议、时限、绑定来源与限速条件后才能比较 A/B。

有负载稳态窗口时，按**请求开始时间**预先定义准入窗口，例如 `[稳态开始, 稳态结束 - 全事务超时]`。准入后保留全部成功和失败；不要按完成时间筛掉跨越尾部的慢请求。

## 手机验收表

在原来发生问题的手机和应用上，按真实并发数持续试播 20–30 分钟，再覆盖实际高峰时段。

| 项目 | 记录内容 |
|---|---|
| 环境 | 线路标签、接入方式、手机数量、平台、画质/码率、时段 |
| 持续会话 | 卡顿、掉帧、重连次数，最长停顿及发生时间 |
| 互动 | 评论/互动是否出现明显延迟 |
| 资源 | 两端 CPU、队列、接口及 TCP 重传增量；缺测明确标注 |
| 结论 | 保留、回滚或不确定；写出证据范围 |

合成测试阈值应来自目标业务需求。八小时手册中的改善门槛是操作筛选规则，不是 TCP 标准，也不代表统计显著性。

## 恢复与清理

改动前先确认本地管理入口和 VPS 控制台可用，私下保存原配置。实验卡写明**原值、实际改动对象、运行态恢复命令、持久文件恢复方法、触发条件**。不要猜原 qdisc 或用 `fq` 当作万能回滚值。

拥塞算法默认值主要影响新连接；活动连接的状态需要分别核实。恢复默认值后还要验证新发送连接，不能仅检查 sysctl 或监听 socket。刷新代理连接池可能中断当前会话，应放在维护窗口。

工具本身没有生产修改可回滚。执行者负责停止自己启动的测试服务、采样与抓包，只移除自己新增的精确测试端口规则，删除自己的临时负载文件，保存结束快照，并恢复客户端接入网络。主动停止采集产生的退出码应与业务请求失败分开记录。

查看 [Linux TCP 参数说明](https://docs.kernel.org/networking/ip-sysctl.html) 和 [默认 qdisc 说明](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/net.html#default-qdisc) 时，以目标设备实际内核和接口状态为准；新文档不保证旧设备支持所有选项。
