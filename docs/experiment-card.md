# 单项实验记录卡

复制这份模板到本地私有结果目录。原始地址、socket、备份位置和管理入口可能敏感，公开分享前生成脱敏副本。不要把私钥、密码、UUID、订阅、Cookie 或完整节点配置填进本卡。

## 实验前

| 项目 | 填写内容 |
| --- | --- |
| 实验编号 / 日期 / 时区 |  |
| 主测对象 | 客户端、接入网络、绑定来源、代理路径、目标、方向 |
| 当前业务问题 | 具体触发条件；完成失败、卡顿、重连或尾延迟 |
| 当前配置 A | 与本次假设相关的配置、实际作用连接；不要贴凭据 |
| 怀疑的机制 | 一句话，能被本次测量支持或否定 |
| 已有证据 | 完成率、固定对象时间、实际 socket、资源/计数增量 |
| 唯一候选 B | 精确的一项改动及影响范围 |

| 对真实业务的影响 | 是否需要维护窗口、重建连接或中断会话 |

| 精确回滚步骤 | 还原哪一项、读取核对方法、业务确认；先准备后改动 |

## 样本登记

成功和失败都写入；不要覆盖旧结果。先按请求开始时间确定统计窗口，不得按结果好坏重新挑窗口。

| 顺序 | A / B | 开始时间 | 连接生效证据 | 预期字节 | 实际字节 | 最终 HTTP / 退出状态 | 完成时间 | 完成 / 失败 | 同时资源或业务异常 |

| 1 |  |  |  |  |  |  |  |  |  |
| 2 |  |  |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |  |  |

可安全快速切换时采用交错次序，例如 `AB → BA → AB → BA → AB`。生产接口队列或会话切换具有影响时，采用维护窗口一次验证，明确对照的局限；不要机械重复切换。

## 结果与交接

| 项目 | 必须写清楚 |
| --- | --- |
| 总样本分母 | A 和 B 各多少次、多少完成、多少失败、缺失原因 |
| 完成样本性能 | 相同任务完成时间中位数、有效吞吐，不能用部分超时任务冒充完整吞吐 |
| 波动与保护条件 | 改善是否大于 A 自身波动，失败和资源是否恶化 |
| 决定 | 保留 B、回滚 A，或结果不确定 |
| 支持的判断 | 配置有业务收益、机制旁证，还是根因已被独立复核 |
| 未确定事项 | 不能被当前测试证明的定位、容量或真实业务结果 |
| 当前实际配置 | 实际生效状态、持久化读取核对；测试 socket 选项单列 |
| 收尾状态 | 测试进程、临时端口、采样文件、客户端网络恢复 |
| 下次验收 | 设备、平台、并发、场景、时间段与失败条件 |

可以预先采用“五对至少四对改善，完成时间中位数缩短至少 20%，且失败和资源没有恶化”作为一次操作筛选线。它不是 TCP 技术标准，不代表统计显著性。原配置有超时而新配置能完整完成同一任务时，先按任务恢复和完成率判断。
