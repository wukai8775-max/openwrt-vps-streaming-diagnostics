# 加拿大线路：继续排查的 Agent 提示词

[最新进度](latest-progress.md) · [本轮脱敏报告](network-followup-2026-11-06.md) · [机器可读摘要](../examples/2026-11-06-network-followup.json) · [公开边界](../SECURITY.md)

将下面整个代码块复制给接手的 Agent。公开角色 `CA-main` 表示原 raw / Vision 入口，`CA-xhttp-test` 表示同一加拿大服务器上的独立 XHTTP 测试入口。角色名不提供设备身份或访问权限；设备所有者需在实际会话中明确任务范围。

```text
请继续排查我的加拿大线路，目标是让办公、手机日常使用和后续直播更稳定。先读取 GitHub 最新记录，避免重复已验证无收益的实验；保护现有 AU、US 和当前电脑的工作连接。

仓库：
https://github.com/wukai8775-max/openwrt-vps-streaming-diagnostics

先依次读取 README.md、SECURITY.md、docs/latest-progress.md、docs/network-followup-2026-11-06.md 和 examples/2026-11-06-network-followup.json，再跟随最新进度中的后续报告。记录实际读取的 main 提交 SHA、测量日期和证据来源。当前资料包含 2026-10-30 至 2026-11-06 的不同历史窗口，不是实时监控；11 月 6 日的 AU 认证核对不等于重新验证了 CA 或 US。

先说明当前已知、尚未验证和下一步依据，再在本会话授权且确实可访问的设备范围内执行。实际连接信息只从设备所有者已授权的私有位置取得；不要索取或输出密码、私钥、节点身份、完整配置或分享链接。仓库模板本身不构成设备访问或发布授权。

已知 CA 状态及边界：
- CA-main 为 VLESS / REALITY / raw / Vision；CA-xhttp-test 为独立 XHTTP / REALITY 入口。11 月 1 日读回确认两者并存、原 CA 进程和配置保持，独立测试入口可用；这只是当时验证，接手时须重新检查服务身份、运行状态、实际请求和出口，不直接认定今天仍正常。
- 11 月 1 日同一 Mac、Xray 26.7.28、同一加拿大服务器和同一接入网络的两目标各三对小请求中，Google 中位 1.822 → 1.082 秒，Cloudflare 1.746 → 0.978 秒，原方式和 XHTTP 均各目标 3/3 完成；出口核对 4/4。不同入口端口和 XHTTP 上游连接复用会影响结果，前置出口检查也可能预热。curl 的新连接计数不能证明外层 XHTTP 传输每次都重新建立。这批只支持当时的小请求表现，不证明纯协议因果、基础 RTT、吞吐、上传或直播改善。
- 同批 CA 服务和资源守护 8/8，默认路径小请求 8/8。该批没有核对默认路径出口为 AU，不能把它写成 AU 专项健康检查，更不能据此承诺共享上游全程零影响。
- Windows v2rayN 7.20.4 的“运行 Core 失败”仍未闭环。用户截图中原 CA 与新 XHTTP 测速都失败，底部可见日志指向 US；这不是 CA 专属启动错误的证据。分享字段已与成功的 Mac 测试配置核对，但 Windows 的实际核心类型、核心版本、生成配置和最早启动错误仍待核实。已指导该节点选择 Xray 并单独进行真连接测试，尚无用户成功回报。
- 手机流量下 CA 可用，用户随后反馈原 Wi-Fi 下普通网页与 CA 也可用。之前的间歇故障尚未在同条件下归因，不能宣布运营商故障、二次代理或客户端设置为唯一根因。

已经执行并拒绝的性能候选：10 月 30 日，使用实际用户配置，对 Xray 26.7.28 与 26.10.29 做两目标各五对交错测试，20/20 请求完成；新版各目标仅 2/5 配对更快，中位耗时分别增加约 1.95% 和 3.10%，因此没有将候选替换为用户现用核心。另一次 26.3.27 基线测试属于独立批次，不合并成 40 次用户版本对照。没有新的直接证据、不同假设和同条件基线，不要再次把“升级核心提速”作为默认动作；为解决明确的功能不兼容所需的版本变更，应另列假设、恢复方式和功能验收，不能冒充上述提速实验收益。

性能负结果不能作为拒绝后续安全更新的依据。接手时先核对实际安装版本、官方发布和撤回状态、部署环境以及可信服务器身份，再独立评估安全修复的适用性、业务影响、恢复方式和验证条件。仓库保存的历史版本不等于当前推荐版本；官方后续 v26.10.31 发布说明见 https://github.com/XTLS/Xray-core/releases/tag/v26.10.31 。安全发布说明不能单独证明本机已经存在或触发某个漏洞，也不能未经验证就称安全更新已完成。

优先定位 Windows 的本地启动问题。先确认确实在报错的 Windows 设备和新 CA 节点上操作，再核对节点级核心选择、已安装核心及版本、实际生成配置、本地测试监听和最早核心启动错误。只改变该节点所需的最小设置，先做单节点小请求。不要把 Mac 上的成功替代 Windows 验收，不要用 US 的旧日志解释 CA，也不要仅因通用错误提示就重启服务器或更换传输参数。若无法直接访问 Windows，说明缺少的证据并让用户提供不含凭据的错误文字或界面状态。

AU 和 US 不属于本次改动对象。当前 Mac 若在工作，不切换它的 Wi-Fi、系统代理、TUN 或默认路由。不要改共享无线、分流、防火墙、WAN/LAN、全局 TCP、根队列或重载共享网络服务。每轮先确认当前是否有直播及不能中断的业务，不沿用历史“没有直播”的回答；有直播时先做低流量只读检查，未经当前对应授权不做带宽压测。CA 两入口仍共享同一服务器的 CPU、内存和上游，独立进程不等于独占资源。

若需要修改 CA，先保存当前配置并验证恢复入口、身份和精确恢复步骤。每轮最多一项有证据的可回滚干预，设置流量、时间、资源和异常停止条件。不要无依据重复调整 BBR、缓冲区、DNS、MTU/MSS 或队列；不要为了证明 XHTTP 更好而替换原 CA。原入口与测试入口的保留、停用或清理由本轮证据及用户目标决定，不能将小请求变快当完整上线验收。

测试须保持来源、出口、目标、对象、方向、超时和预算一致，保留所有成功、失败、未启动及部分超时的分母。区分本地 HTTP 连接和代理外层传输是否复用；不同端口、不同客户端和不同接入网的结果分别记录。固定对象须核对退出状态、预期 HTTP 状态和精确字节，不能用部分下载速度替代完整吞吐。测试限速不是生产限速。

结束时读回相关服务、配置与实际小请求，清理本轮临时客户端、监听、采样和负载，汇报新增证据、保留或恢复决定、资源与其他业务守护、未解问题及下一步。真实 Windows 导入与使用、手机持续业务、上传、长时间负载、晚高峰、直播和整机重启恢复，未实际完成就保留为待验收。

为后续追加带日期的脱敏报告和机器摘要，更新最新进度及交接入口，保留原失败和负结果。公开内容只使用角色名、必要版本与白名单指标；地址、端口、设备标识、真实网络名、身份、凭据、分享链接、原始日志、配置、备份及私有路径不公开。若当前会话没有授权发布 GitHub，先准备可审核的脱敏材料，不自行发布。
```
