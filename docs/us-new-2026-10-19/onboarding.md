# WEPC US-new 接入与有限验收记录

> Public snapshot: 2026-10-19; network identifiers use role labels. Original configurations, addresses, credentials and raw evidence remain private. Read [the handoff and experiment ledger](index.md) for the final decision.

日期：2026-10-19（Asia/Shanghai）。用途：办公和手机日常使用为主，直播较少。

后续已完成一轮带宽定位与参数对照，详见 [US-new 带宽定位与实验记录](round1-throughput.md)。该轮 BBR 和强制接收缓冲候选均未通过保留条件，生产配置已恢复；不要将不同文件大小的测试结果误认为优化收益。

原生 TCP 接收缓存自动调节上限的第二轮对照另见 [US-new 自动接收缓存对照记录](round2-autotune.md)。两轮采用不同机制，结果和最终保留决定分别记录；本页下列数据仍是初次接入时的历史验收。

最新的其他瓶颈及同Wi-Fi路径对照见 [第三轮记录](round3-bottlenecks.md)：12/12公网请求完整；独立本地无线下载3/3，535–612Mbps。两阶段临时单源规则和服务均已撤，原生产配置保留；短时本地吞吐不代表公网容量或手机直播验收。

本轮已建立 US-new，并分别完成独立 Mac SOCKS 测试、实际路由器 Wi-Fi 出口测试及两条路径分别进行的短时有限负载。结果支持继续小范围使用和观察；尚未达到真实手机直播、Claude 登录后长会话或晚高峰的完整验收。数据来自受保护目录中的指定验收 JSON；配置与故障处置事实由主实施线程提供。本文未复制地址、完整客户端配置或凭据。

## 当前配置与范围

- 新服务器使用官方 Xray 26.3.27，VLESS / REALITY / raw / Vision。
- 新VPS保持 cubic / fq_codel；路由器原默认拥塞算法为BBR。两者角色分别记录，本轮没有通过修改拥塞控制或队列参数取得结果。
- US-new 最终持久配置与运行配置一致。旧 US 云服务器尚未取消。
- 独立 Mac SOCKS 三路上传的 **15 Mbps 是测试总预算，每路约 5 Mbps**；真实 US-new Wi-Fi 三路上传的 **9 Mbps 是测试总预算，每路约 3 Mbps**。两者都不是生产线路限速，也不能据此认定线路容量上限。

实际 Wi-Fi 三路上传的汇总墙钟为 70.388 秒，包含小请求探测收尾；按这一墙钟计算的对象 goodput 为 8.581 Mbps。该值包含收尾等待，不是线路容量上限，也不能解释为每路传输未达到 3 Mbps 预算。

实际 Wi-Fi 的小 HTTPS 总请求时间中位数为 1.588 秒，独立 SOCKS 为 0.895 秒。这些是顺序、小样本测试，不能据此精确归因某一层的额外延迟。吞吐采用完整对象事务时间，包含建连与响应等待；它不是持续链路容量。

首组 Wi-Fi UDP 每次新建 socket，本地 UDP 检测则复用 socket，两组不能直接比较路径延迟。实际 Wi-Fi 另做同一持久 UDP 流的 6/6 次探测：首次 1253.640 ms，后五次的中位数为 315.080 ms。初次与后续响应明显不同，仍需在真实应用中观察；不能把它解释成所有 UDP 的固定延迟或抖动结论。

## 已发生的中断与修复

1. 最初切换 US SSID 时，空桥被销毁，出现 Wi-Fi 能连接但无法取得 DHCP 地址的情况。这是一次实际接入失败，不能只保留后续成功样本。
2. 修复过程间接导致 AU-group-2–AU-group-5 短时重关联；已向用户说明。**本轮并非零 AU 影响。**
3. 用户允许后执行一次 network reload，并增加 `network.<US_SECTION>.bridge_empty=1` 保留空桥。此处 `<US_SECTION>` 是内部网络 section 的占位符；公开线路角色为 US-new。
4. 随后 AU-main–AU-group-5 已恢复，US-new 持久配置与运行配置读回一致；上述真实 Wi-Fi 验收是修复后的测试。

## 路由与嵌套代理核对

主线程及路由审计读回：US 业务出站没有 `dialerProxy` / `proxySettings`；DNS 辅助出站的引用指向 US 自身。新服务器直连集合与 mark 255 规则位于 AU 规则之前；观察到的 7 个 US 已建立连接均指向新服务器 TCP 443。该快照没有 AU 嵌套代理证据；它是当时的配置与连接核对，不能证明所有未来连接的映射。

服务端连接来源另与管理连接的直连来源交叉核对一致，未观察到 AU 出口来源。最终 AU / US 轻量请求 4/4 收到 HTTP 200；这是有限健康检查，不代表持续业务全量验证。

## 办公目标的公开请求检查

在真实 US-new Wi-Fi、显式绑定无线接口并绕过系统显式代理的条件下：

| 目标 | HTTP 结果 | 能证明和不能证明的内容 |
|---|---:|---|
| Claude 公共页面 | 403 | 检出 Cloudflare challenge 标记，未检出显式地区拒绝标记；不能据此称 Claude 登录或对话可用 |
| Anthropic API，无密钥 | 401 | 收到未认证响应；没有执行带密钥 API 业务 |
| GitHub 公共页面 | 200 | 该次公开页面请求完成 |

以上没有使用 API Key 或 Cookie；未检测到某类标记不等于符合地区资格或已经通过账号风控。Claude 登录、长会话和实际回复仍需用户实际验收。

## 流量预算与解释边界

指定文件记录的主体数据对象合计 **256,492,416 字节（约 256.5 MB）**。这只包括已列的下载/上传对象，排除安装更新、协议开销、轻量探测和其他请求，不能当成商家计费流量总额；退款门槛仍需看实际产品条款和控制台计数。不得为追求数字而在试用初期无预算持续压测。

成功分母分别保留，独立 Mac SOCKS 与实际路由器 Wi-Fi 的三路负载分别记录，预算也不同，不能混为一次验证，也不把 11/11 HTTPS 或 5/5 STUN 换算为直播丢包率。没有在相同时段、相同条件下完成旧 US 与新 US 的性能 A/B，因此本文不宣称改善百分比。
