# 美国线路双路 RTMP 推流验收 · 2026-11-16

两路 720p30 的 RTMP 推流在同一条美国线路上并发运行约 **20 分 02 秒**。每路接收端的 TCP 平均速率约 **4.19 Mbps**，各发出并收到 **36,000 帧**。两路正常结束，接收期间没有观察到断流、重连或达到 2 秒的帧数停顿。[机器摘要](../examples/2026-11-16-us-dual-rtmp.json)

## 测试路径与负载

一台测试电脑通过 Wi-Fi 接入路由器，两路经过路由器上正在使用的美国代理和美国 VPS，由独立的加拿大自有接收端接收。接收端的地址命中路由器的代理节点直连规则，因此测试电脑使用两条临时本地转发连接，把两路流量分别交给路由器的生产 SOCKS 入口。接收端只允许预期的美国出口接入，两路各有 223 次已连接的对端核对，全部匹配。

使用有运动画面和音频的合成素材，视频为 H.264、1280×720、30 fps、约 4 Mbps，关键帧间隔 2 秒，音频为 AAC、128 kbps。正式推流前先跑了双路约 12 秒，每路均收到 360 帧。正式批次每路媒体时间 1,202.328 秒，接收端按约 0.5 秒的周期报告帧数和媒体时间。发送端与接收端独立保存进度。[FFmpeg RTMP 协议文档](https://ffmpeg.org/ffmpeg-protocols.html#rtmp) · [直播编码设置参考](https://support.google.com/youtube/answer/2853702)

## 正式批次结果

| 指标 | 第一路 | 第二路 |
|---|---:|---:|
| 发送 / 接收视频帧 | 36,000 / 36,000 | 36,000 / 36,000 |
| 发送端报告的掉帧 / 重复帧 | 0 / 0 | 0 / 0 |
| 接收平均 TCP 速率 | 4.194 Mbps | 4.194 Mbps |
| 接收进度报告的最长间隔 | 0.515 秒 | 0.528 秒 |
| 接收帧计数两次增长之间的最长间隔 | 0.515 秒 | 1.000 秒 |
| 达到 2 秒的帧计数停顿 | 0 | 0 |
| 观察到的断流 / 重连 | 0 / 0 | 0 / 0 |
| 发送 / 接收进程退出码 | 0 / 0 | 0 / 0 |

进度报告可能发出时帧数尚未增加。判断接收停顿时，使用帧计数两次实际增长之间的间隔，排除起步和主动结束。第二路的两项最大间隔因这一口径而不同。

路由器在双路同时运行的 39 个完整采样窗口内，WAN 总上行为 9.40～11.64 Mbps，含同期其他流量。接口收发硬件错误和发送丢弃计数均未增长。接收日志的错误关键词扫描每路各命中一次，原文未留存，类型和原因未确认。

## 复测与收尾

1. 在受控接收端限制允许的来源，并为临时监听和访问规则设置到期清理。先用短推流确认双方帧数一致、接收来源与预期出口匹配。
2. 同时启动两路等码率流。记录媒体时长、发送和接收帧数、退出状态、重连，以及接收帧数在运行中的增长间隔。用带时间戳的进度发现中途停住后又补齐的情况。
3. 结束后核对两端帧数、进程状态和接收来源，再关闭临时监听、撤销规则并恢复测试电脑的原网络。本轮临时接收端、规则、定时器和本地转发均已清理，电脑恢复原网络并通过 HTTPS 请求。

本轮证据覆盖单台电脑模拟的双路 RTMP 上传。两台手机分别关联 Wi-Fi、平台接收和观众播放仍待实测。单次 20 分钟的结果只适用于本次路径、码率和测量窗口。
